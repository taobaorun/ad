Bundle 瘦身 — Monaco → CodeMirror 6

根治主窗口和 Settings 窗口启动时的「空白页 → 内容」过渡感。问题根因不在窗口显示时机，而在首屏 bundle 体积 — 当前主 chunk 是 3.7 MB（Monaco editor 全量打包）。WebView 要等这个 bundle 下载/解析/执行完成才能 paint UI，所以哪怕 OS 窗口已显示，里面也会有几百毫秒到一两秒的空白。

根因分析

为什么会"先空白再出内容"

┌─ OS 创建 Tauri 窗口 [已 backgroundColor 兜底，第一帧不再白] │ ▼ ◯ WebView 加载 index.html ← 同步 inline script: 涂主题色 │ ▼ ◯ 下载 /assets/index-*.js (3.7 MB) ← 阻塞点 ① │ ▼ ◯ 解析 + 执行 Monaco 模块图 ← 阻塞点 ② │ ▼ ◯ React 首次 render → UI 可见 ← 这才离开"空白态" 阻塞点 ① ② 加起来 = 用户看到的"过渡感"。换 CodeMirror 后两点都消除。

假设

开始前的隐含前提

A1
CodeMirror 6 在 Tauri 2 WKWebView 上运行良好。纯 ESM、无 worker、无平台依赖。
A2
现有 CSP（default-src 'self'; ...; worker-src 'self' blob:）对 CodeMirror 不需要任何调整。
A3
@codemirror/lang-json 提供的高亮 + 括号匹配 + 折叠 + 自动闭合已满足实际需要；用户对 JSON schema 自动补全无强需求。
A4
JSON 校验由父组件 LayeredSettingsEditor 完成（沿用现有 parseLayer + onValidityChange），编辑器内部不画 gutter marker。
A5
dark/light 主题切换通过 EditorView.dispatch 重新配置 extensions 实现，能在 useUiSettings.darkMode 变化时无缝切换。
A6
DiffView.tsx 是死代码 — grep -rn "DiffView" src/ 全仓只匹配自身定义。
A7
之前加的 backgroundColor + 预绘脚本保留作为兜底，但根治后过渡时间应该 < 100 ms，不需要再补 deferred-show。
A8
移除 monaco 相关 deps 后，Vite 不再产出 *.worker-*.js 文件。
关键决策

方案选型

D1

用 CodeMirror 6 替代 Monaco

体积差 30-50 倍（3 MB+ vs ~80 KB gzip），功能覆盖 100% 实际需要的（JSON 高亮、行号、暗色主题、撤销重做、查找替换）。否决「保留 Monaco + lazy」 — bundle 总量不变；否决「textarea + Prism」 — 失去行号/查找/撤销栈。
重写 ~150 行 收益最大
D2

抽出 JsonEditor 组件

CodeMirror 命令式 API 与 React 受控模式有阻抗。把这层封装在组件边界内，对外仍是 value / onChange，LayeredSettingsEditor 不感知差异。将来换其它编辑器只动一处。
关注点分离
D3

JSON 校验留在父组件

当前 parseLayer + onValidityChange 已经把校验放在父层；CodeMirror lint 也能做但会重复。保持单一来源。
单一来源
D4

路由级 split 走 dynamic import

保持 vite/index.html 单 entry 模型不变。main.tsx 根据 hash 动态 import App / SettingsApp，Vite 自动产出独立 chunk。否决双 entry — 要改 vite multi-page 配置 + AdvancedSettings.tsx url 拼接，工程量更大。
小改动
D5

保留 backgroundColor + 预绘脚本兜底

无害（CodeMirror 加载快后 1-2 帧内被 React 接管），但万一某机器加载稍慢，至少首帧不是白色。不再需要 deferred-show（visible:false + frontend ready 后 show）— 根治后过渡 < 100 ms 肉眼不可见。
defense-in-depth
D6

不做 i18n locale lazy

zh.json + en.json 加起来 ~30 KB，相对收益太小，不值得复杂化（要异步等 locale 加载完才能 render）。
收益不足
D7

vite manualChunks 分组

vendor-react: react/react-dom/react-i18next；vendor-codemirror: codemirror/@codemirror/*；vendor-radix: @radix-ui/* + cmdk + lucide-react。让构建产物结构更可读，开发期 reload 速度也有帮助。
缓存友好

M1
deps · cleanup

基础设施 + 死代码清理

删除 DiffView.tsx / monacoSetup.ts；从 main.tsx 移除 import './lib/monacoSetup'；pnpm remove monaco-editor @monaco-editor/react；pnpm add codemirror @codemirror/state @codemirror/view @codemirror/lang-json @codemirror/theme-one-dark。

M2
code · new component

新建 JsonEditor.tsx

M3
code · replace

LayeredSettingsEditor 接入 JsonEditor

import Editor from '@monaco-editor/react' → import { JsonEditor } from './JsonEditor'；移除 Monaco 特有 options（minimap/fontSize/word-wrap）— CodeMirror 默认已合理。

pnpm typecheck 通过；pnpm tauri build 成功；dist/assets 不再出现 monaco chunk
M4
split · routes

路由级 split

main.tsx：根据 window.location.hash.startsWith('#/settings') 动态 import('./App') 或 import('./SettingsApp')；用顶层 await 或 IIFE 包裹。

dist/assets 出现独立 App-*.js 和 SettingsApp-*.js；Settings chunk 不引用 codemirror
M5
split · components

大组件 React.lazy

App.tsx 顶层把 HistoryDialog / ImportDialog / DetectedProjectsModal / CommandPalette / ProfileEditDrawer 改成 React.lazy（默认隐藏的 dialog/drawer，<Suspense fallback={null}> 即可）。ProjectDetail.tsx 把 ProjectConfigEditor 改 lazy，外层用 <Suspense fallback={<EditorSkeleton />}>。

每个 dialog/drawer 首次打开时按需加载，无报错
M6

vite manualChunks

vite.config.ts 在 build.rollupOptions.output.manualChunks 配置 vendor-react / vendor-codemirror / vendor-radix；chunkSizeWarningLimit: 800。

pnpm tauri build 后 chunk 分布合理，主 bundle < 600 KB

验证 + 部署 + 文档

typecheck + test + build 全绿；部署到 /Applications/AD.app 肉眼验证主窗口和 Settings 窗口启动；JSON 高亮、行号、暗色主题、撤销重做、Cmd+F 全部正常；非法 JSON 红框报错；darkMode 切换主题跟随；⌘K palette / dialog 按需加载。更新 AGENTS.md 项目结构，归档 MD+HTML 到 completed/。

主 bundle < 600 KB；窗口空白过渡 < 300 ms（目测）
