ExecPlan · Stage 2 评审版

集成外部终端启动 Claude

让 AD 在选中 project 后一键到外部终端里以正确 cwd 启动 claude。支持 Ghostty / cmux / Terminal.app / 自定义命令，launcher 接口从一开始就抽象，方便后续扩展。

待用户确认 · 评审中
01

目的

用户在 ProjectDetail 主区按 Open in terminal 按钮，AD 在用户配置的终端里以当前 project 路径为 cwd 启动 claude。首次开新窗口，已有窗口开新 tab，窗口被关掉则自动回退新窗口。终端 backend 在 Settings 里可选。

env 仍由 CC 自己从 <project>/.claude/settings.local.json 读取——launcher 不负责 export env。

02

假设（显式列出，不沉默）

env 边界CC 启动时自动从 settings.local.json 加载 env，launcher 只需 cd + 起 claude。
claude 二进制默认依赖 PATH，可在 Settings 覆盖为绝对路径，launcher 不自己探测。
macOS only所有适配走 macOS 原生（open -na / osascript），不为其他平台留接口。
窗口存活检测通过尝试 AppleScript / CLI 命令失败回退，不维护额外的 PID/socket。
cmux 自管 tab/windowAD 只透传 path，不解析 cmux 的 workspace/window/pane 模型。
不持久化"上次终端"每次按按钮都是冷判断当前 project + 当前 backend。

05

关键决策

D1 · 架构

Rust enum 而非 trait object

后端集合封闭（4 个），enum 在 Tauri 序列化、settings 持久化、match 穷尽性检查上都更顺手。

替代：Box<dyn TerminalLauncher>——更"OO"但带 Send/Sync 与一层间接，不划算。

D2 · 平台限制

Ghostty 新 tab 走 osascript

macOS 上 ghostty +new-window 明确返回 not supported on this platform。CLI 只能 open -na 每次开新窗口。tab 复用必须 AppleScript。

这是上游限制不是临时缺陷,osascript 失败时自动回退到 open -na 新窗口。

D3 · 不重复造轮子

cmux 透传 path,不管 tab/window

cmux 的 cmux <path> 已经做到"没运行就启动 + 已运行就开 workspace"。AD 介入会和它的产品模型冲突。

代价：cmux 用户感受不到 AD "新窗口 vs 新 tab"开关。UI 用 helper text 说明。

D4 · 扩展性

Custom 用 {{cwd}}/{{cmd}} 模板

示例 open -na WezTerm.app --args start --cwd {{cwd}} -- {{cmd}}。比让用户写 shell 脚本可控得多。

单测覆盖几个常见 wezterm / alacritty 模板,降低 quoting 翻车风险。

D5 · 边界

不在 launcher 里 export env

v0.4 已经把 env 写到 .claude/settings.local.json 顶层,CC 启动自动加载。launcher 只 cd + claude。

单一职责,避免和 CC 的 env 加载逻辑漂移。

D6 · 配置范围

终端偏好存用户级,不跟 project 走

写到 ~/.ad/settings.json。同一用户在所有 project 里用同一终端是合理默认。

未来如果有强需求再加 project-level 覆盖,现在不做（准则 2：最小实现）。

10

幂等性 / 回滚

  • 所有 launch 都是"启动新东西",本身幂等（重复点会开多个 tab,符合预期）
  • 失败不修改任何持久化状态,只 Err 返回给前端 toast
  • Settings 改 backend 不影响已经起来的终端窗口
  • 回滚：删 terminal/ 模块 + revert UI 改动即可,无 schema 迁移
