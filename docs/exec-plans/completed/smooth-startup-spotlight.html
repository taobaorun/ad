最终架构：把绘制从冻结的页面主线程移开

Tauri 在导航开始时显示主题匹配的窗口。同步首屏脚本保留真实 <p>，并将覆盖 Canvas 转交给独立 Worker；即使初始化阻塞页面主线程，Worker 仍按自己的定时器推进像素。

旧 WKWebView 无 OffscreenCanvas 时回退主线程定时器；Canvas 不可用时回退可见真实文案。

运行合同

01 首屏同步创建

文案与绘制面不等待 React bundle。

02 主题与尺寸测量

读取 computed font、颜色、bounds 与 DPR。

03 Worker 主动重画

16ms 定时推进 300ms、55% 句宽光带。

04 变化同步

文案或尺寸变化发送给 Worker。

05 初始化完成

立即揭幕、移除 Canvas、终止绘制。

决策演进：每次替换都有实机证据

最终方案不是最初计划的机械实现。真实安装包连续暴露 WKWebView 的启动期绘制差异，计划依次收敛到与页面主线程隔离的 Worker。

01

连续 rAF + 文字渐变

替换 50ms / 5 段量化位置，但安装包中的 clipped-text background 未可靠重绘。

02

逐字符 opacity

Chrome 正常，WKWebView 退化为单字符；绝对 delay 也无法修复多元素 stagger。

03

双层句子 + clip-path

最小探针 computed value 会推进，真实 Tauri 安装包仍无可见效果。

04

Canvas + rAF / 主线程定时器

普通 WKWebView 能更新像素，但 Tauri 隐藏窗口与启动命令会冻结页面主线程。

05

Worker OffscreenCanvas

与页面主线程隔离；人为同步阻塞主线程 600ms 时，quote 区域仍持续变化，成为最终实现。
