AD 多 Agent 支持

状态：待用户确认
Claude Code 与 Codex 通过内置 Adapter 实现能力对等。跨 Agent 转换生成独立目标配置，源配置不变；目标已存在时先预览差异和无法转换字段，再备份、写入并支持回滚。

目的 / 全局视角

将 Agent-specific 文件系统和配置语义隔离在 adapter 中，让统一 UI、profile、history、backup 和 capability 层可复用。首期不开放用户自定义 adapter。

关键决策

Contract
  • AgentId + Capability + Adapter registry。
  • profile 使用 (agentId, profileId) 复合身份。
  • 发现结果按 canonical identity 去重，只保留 canonical installation。
Safety
  • Claude Code 源配置只读不改。
  • 目标存在时先 diff/unsupported preview。
  • 确认后备份目标；写入失败恢复目标。

风险与缓解

High

Codex 文件格式或能力边界随版本变化。
缓解：adapter 内 discovery + inspection；未知格式拒绝静默转换。

High

跨 Agent 字段不等价。
缓解：转换结果分级并要求 unsupported/confirmation preview。

Medium

Claude 逻辑分散导致回归。
缓解：先 façade 化，保留兼容 IPC，逐步替换调用点。

Medium

多来源发现重复。
缓解：统一 canonical identity 归一化和 fixture 测试。

验证和验收

  • Claude Code 与 Codex profile、history、backup 不串写。
  • 重复 discovery 只展示一个 canonical installation。
  • Claude → Codex 不修改 Claude 源配置。
  • 目标存在时必须先显示 diff 和无法转换字段。
  • 确认后才备份并写入 Codex；失败可恢复目标原状。
  • pnpm typecheck、pnpm lint、pnpm test、cargo test、pnpm build 全部通过。
