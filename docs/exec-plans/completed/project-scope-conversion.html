作用域边界

当前后端已有 Project 路径能力，但会同时扫描 User 与 Project；UI 又从未传入项目路径。本计划同时补齐可达性和隔离性。

关键决策

不引入新的 Agent 专属命令或第二套项目选择状态。

1

projectPath 推导唯一 scope

无 projectPath 为 User；有 projectPath 为 Project。route 只处理该 scope 的 Settings、Skills 和 Plugins。

2

绑定当前项目

复用主窗口当前选中项目；Project 模式先由后端 canonicalize 两端 context。

3

保持 backend-owned plan

前端只显示 artifact 和提交 planId，不能指定物理路径或 mutation 内容。

实施步骤

每个增量先写失败测试，再做最小实现并验证。

1. 后端作用域不变量

集成测试复现 Project route 混入 User；过滤后验证真实 apply / rollback 只触达项目目标。

2. UI 可达性

加入 User / Project selector；Project 绑定当前项目并清除失效的旧 plan/receipt。

3. 文档与交付

同步中英文、as-built 设计和产品规格；跑全量门禁后构建、备份、安装并只读验收。

验收清单

User 模式不带 projectPath，只触达 Codex user config。
Project 模式只触达当前项目 .codex/config.toml。
Claude user/shared/local 与 Codex user 配置字节保持不变。
shared/local 按 local 覆盖后转换，冲突仍可见。
目标有备份，rollback 恢复；外部修改后拒绝静默覆盖。
前后端全量检查、生产 build、签名和原生只读验收通过。
