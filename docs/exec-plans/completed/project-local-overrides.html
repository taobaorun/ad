让 Profile 成为真正的"模板"——各 project 可在 profile 基础上添加自己的本地配置，切换或重新 apply profile 时这些配置不会被覆盖。

核心逻辑

新 Apply 公式

local 层不再 merge 已有的 settings.local.json，而是由 profile.local 和 project.local_overrides 完整重建。

settings.local.json
←
merge(profile.local, project.local_overrides)
overrides 文件存储位置：~/.ad/state/local-overrides/<path-hash>.json  ·  如果 project 没有 overrides 文件，等价于旧行为（只写 profile.local）
影响范围

修改的文件

关键决策

设计取舍

D1

Overrides 存独立文件

不放入 projects.json。JSON 内容可能较大，注入注册文件会让它无限膨胀，且独立文件便于调试和备份。路径哈希与现有 backup slug 策略保持一致。

简洁 可调试
D2

Apply 时不 merge 已有 settings.local.json

新公式 merge(profile.local, overrides) 让 apply 结果幂等、可预期。手动编辑 settings.local.json 的内容在下次 apply 后丢失——这是预期行为，因为该文件是 AD 的输出文件。

幂等 手动编辑会丢失
D3

不做向前迁移

不将已有 settings.local.json 里的"额外内容"自动迁移为 overrides。实现复杂且容易出错，用户可在 UI 里手动补回需要的内容。行为变更会在 UI 里有文字提示。

一次性丢失风险 低实现风险
D4

UI 放 ProjectDetail 新 section

不新建独立 tab。ProjectDetail 已有 CURRENT / APPLY DIFFERENT / RECENT 三区，新增 PROJECT LOCAL 区块展开时显示 Monaco 编辑器，折叠时显示 override key 数量摘要。与 ProfileEditor 的编辑体验保持一致。

复用现有 UX Monaco 一致性
前提假设

隐含条件

A1 Overrides 仅作用于 settings.local.json（local 层），不影响 settings.json（shared 层）
A2 Overrides 存在 ~/.ad/state/local-overrides/，不在项目目录内（对 git 透明）
A3 向后兼容：project 没有 overrides 文件时，行为与当前一致（等价于只写 profile.local）
A4 不支持 env 层 overrides——env 层已有独立机制（export 片段），不在本次范围内

实施步骤

Step 1
BACKEND

paths.rs — 新增路径函数

新增 local_overrides_dir() 返回 ~/.ad/state/local-overrides/，以及 local_override_path(project_path) 用项目路径哈希生成对应文件路径。

cargo check 通过；单测路径格式正确
Step 2
BACKEND

projects.rs — 新增 get/save 命令

新增 get_project_local_overrides(project_path) 读取 overrides 文件（文件不存在时返回空对象），以及 save_project_local_overrides(project_path, content) 原子写入。

手动 invoke 返回正确 JSON；不存在时返回 {}
Step 3
BACKEND

apply.rs — 修改 local 层逻辑

write_layer() 的 local 分支：从 local_override_path() 加载 overrides，执行 merge(profile.layers.local, overrides) 后原子写入目标项目，不再读取已有的 settings.local.json。

apply 后内容 = merge(profile.local, overrides)；空 overrides 等价于旧行为
Step 4
BACKEND

lib.rs — 注册新命令

在 tauri::Builder 的 invoke_handler 中注册 get_project_local_overrides 和 save_project_local_overrides。

cargo check 通过
Step 5
FRONTEND

类型 + IPC

projectTypes.ts 新增 ProjectLocalOverrides 类型（即 Record<string, unknown>）；tauri.ts 新增 getProjectLocalOverrides() 和 saveProjectLocalOverrides() 封装。

pnpm typecheck 通过
Step 6
FRONTEND

ProjectDetail — PROJECT LOCAL 区块

在 ProjectDetail 底部新增可折叠的 PROJECT LOCAL 区块。折叠态显示 key 数量摘要；展开后显示 Monaco JSON 编辑器（与 ProfileEditor 一致），底部有 Save 按钮。保存后触发 saveProjectLocalOverrides()，并提示用户重新 apply 生效。

能保存 override；切换 profile 后 overrides 仍存在；重新 apply 后 settings.local.json 包含 overrides

新增 projectLocal.* 命名空间：区块标题、key 数量摘要、Save 按钮、行为变更提示（"手动编辑 settings.local.json 的内容在下次 apply 后将被覆盖"）。

无 raw key 展示；zh/en 全覆盖
