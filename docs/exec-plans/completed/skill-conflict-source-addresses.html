01

问题与目标状态

后端已经知道同名 Skill 属于不同 source group，但 inventory 只向前端留下 opaque ID。当前 UI 只能拿 description 当来源名，因此用户看到“存在冲突”，却不知道该处理哪一个目录或仓库。

现在：冲突可见，来源不可核验

两个 html-artifact 都显示为只读冲突。来源 chips 可能只是“Personal tools / Team tools”，也可能直接变成“未知来源”。

目标：每个候选都有明确地址语义

Catalog 候选显示 acquisition source；没有 Catalog 记录的 Agent 原生 Skill 显示“当前安装位置”，不把安装目录误说成源仓库。

02

产品与安全合同

本次只增强 provenance 可观察性。冲突继续 fail closed，来源地址不能变成写入能力。

Provenance

一项 resource 对应一个 source group

来源对象放在 ResourceProvenanceView，同时覆盖已安装 declaration 与尚未安装、declarations 为空的 Catalog 候选。

Precedence

Catalog 优先，安装位置降级

组内同时存在 catalog observation 与 snapshot 时展示 acquisition source；只有无法回溯时才显示 installed path。

Security

Rust 输出前完成脱敏

标准 URL 移除 userinfo、password、query 与 fragment。前端只渲染安全结果，不承担 secret 过滤。

Authority

地址永远不是 mutation target

Preview/Apply 继续只接受 backend-issued workspace、inventory 与 resource key；地址不进入 action request。

05

验收标准

完成不是“字段存在”，而是用户能安全地根据地址区分冲突候选。

两个来源，两个明确地址同名 Skill 的候选数、来源行数和实际 source groups 一致。
Catalog 语义不丢失安装后仍显示原 Git/local source；branch 与 subdirectory 可见。
Agent 原生位置诚实标注没有 Catalog 记录时显示“当前安装位置”，不伪称源仓库。
完整且可访问长 URL/路径自动换行、不截断；中英文布局都可读。
无 credential 泄漏inventory JSON 与 DOM 不含 URL username、password、query token 或 fragment。
写入合同零变化冲突继续 read-only；所有 action request 只提交 opaque identity。
