让 AD 主路径更顺手、视觉更协调、对中文用户更友好。三件事打包成一个 ExecPlan， 因为它们都触及"用户进入 AD 的第一印象"，分批改容易出现风格漂移。

问题 ①
添加项目卡在 prompt
CommandPalette 的"Add project from path…"现在用 window.prompt。改成 shell 风格路径补齐，按 Tab/↑↓/Enter。

shadcn 默认 --foreground 是近黑冷调，但 status ring / detected 横幅是暖橙土。改一个 CSS 变量即解。

01

目的 / 全局视角

用户能直接观察到的三件事：

  • ⌘K 输入 add ~/code/ → 实时目录候选，Tab 补齐公共前缀，Enter 添加，路径错误友好提示。
  • 选中的 profile chip / layer toggle 不再是刺眼纯黑底，与左栏色环、detected 横幅的暖色基调一致。
  • 启动默认中文文案；AdvancedSettings 切到 English 立即生效并持久化。
02

假设

任何一条不认同，告知后 MD + HTML 同步修订。

A1 · 入口
路径补齐在 CommandPalette 内（D1）
不另起独立浮层。复用 ⌘K 习惯，0 新窗口。用户已选定 D1。
A2 · 隐藏目录
只列目录，不列文件；隐藏目录需显式 . 前缀
跟 shell 一致，避免噪声。
A3 · 路径展开
~ 展开为 $HOME
其他环境变量不支持（YAGNI）。
A4 · 后端命令
新增 list_directory(prefix)
返回前缀下目录条目，含 is_git_repo 元信息。
A5 · 配色最小化
只改 --foreground/--primary/--ring 三个 token
改为暖深 charcoal（≈ slate #141413）；组件 className 不动。为什么不全 token 重做：问题就在这一颗冷黑嵌进了暖系，改这一处即解；最小修改原则。
A6 · 双语
默认 zh，保留 en 可切换
开发者群体中英分歧大，全删 en 不可逆；可切换最小成本满足"默认中文"。
A7 · i18n 框架
react-i18next（~15KB）
生态成熟、TS 类型完善；不选 lingui / react-intl（更重）。
A8 · 资源组织
按 namespace 切分 JSON
locales/{zh,en}.json，命名空间 common / palette / project / profile / apply / error。
A9 · 持久化
locale 写入 ~/.ad/state/ui.json
复用既有 UI 状态文件，不新建。
A10 · 文档
CODE_STYLE.md 第 68-71 行需更新
原文"AD 是英文界面" → "默认中文，可切英文；所有文案必须走 i18n"。
A11 · 安全
list_directory 不限制路径范围
add_project 本来就接受任意路径（用户自己输的），补齐不引入新攻击面；.. 按字面解析。

04

关键决策

每个决策都列了备选 + 为什么不选。

D1 · 补齐入口
CommandPalette 内（用户已选）
在 ⌘K 输入 add <path> 触发补齐模式。 vs. D2 独立浮层：0 新窗口、复用习惯；用户拒绝原生选择器后明确选了 D1。
D2 · i18n 框架
react-i18next
~15KB；TS 类型完善；插件生态成熟。 vs. lingui / formatjs：更重，编译期提取虽好但 ROI 不足；本项目规模 react-i18next 够用。
D3 · 双语策略
默认 zh，保留 en 切换
兑现 CODE_STYLE.md 既有约束"将来加中文必须走 i18n"。 vs. 仅 zh：不可逆；开发者中英偏好分歧大，可切换最小成本。
D4 · 配色策略
只改 3 个 CSS 变量
--foreground/--primary/--ring 由 222.2 84% 4.9%（冷黑）→ 60 5% 8%（暖深 charcoal）。 vs. 全 token 重做：问题就在这一颗冷黑嵌进了暖系，改一处即解。组件 className 全不动 — 最小修改原则。
D5 · 不缓存目录
list_directory 每次现读
输入节流即可。 vs. 加缓存：缓存复杂度（失效、TTL）超出 MVP，本地 fs 读延迟可忽略。

验收

启动 pnpm tauri dev，依次走完以下 6 步即视为完成。

行为验收

  1. 默认中文：窗口标题、Sidebar 顶部"项目"、CommandPalette 占位符等全部中文
