Executable plan · revised 2026-07-20

实现 Codex Plugin 自动转换与项目隔离运行时

每个项目创建 AD-managed CODEX_HOME：配置与 Plugin state 隔离，ChatGPT 用户登录态跨项目复用；API Key 等项目差异由 Profile 覆盖。

已批准 · 基线已冻结

修改后的目标

Plugin isolation

配置与 Plugin 不污染

Project Preview/Apply 只读默认 config/package；共享 auth refresh 是明确例外。

Inherited config

无需重复配置

AD 每次准备/启动前核验 base digest，合成用户默认配置与 Project Plugin overlay。

Shared identity

项目无需重复登录

文件认证通过受控 auth link 复用；可选 Profile 覆盖项目 API Key 等差异。

主要影响范围

新增的核心不是一个配置字段，而是 project-derived Codex installation、config synthesis、isolated Plugin store 与 launch binding。

架构决策

决策理由结果
Project package → isolated homeCodex 没有 per-project enable state。完整 Plugin 语义且默认 home 不生效。
AD 合成 base configCodex 没有跨 CODEX_HOME include。默认用户配置更新可生成 refresh plan。
config/cache 隔离，auth 共享登录态是用户身份，不应按项目重复；Plugin 写入仍需隔离。文件认证用受控 link；AD 不读取 token。
Keychain 与 Profile 分流Keyring key 按 canonical HOME 隔离；API Key 是项目配置。Keychain-only 阻塞并切共享 Home/Profile；API Key 归 Profile。
Package first保留 Plugin id、version、组件关系与升级语义。仅 legacy package 不可用时拆解组件。
Launch 绑定 installation仅写 project home 不足以保证运行时使用它。所有 terminal backend 注入同一 CODEX_HOME。

明确不做

Sensitive data

不读取认证内容

AD 只管理 auth link 的路径元数据；tokens、sessions、history、logs、SQLite 不进入 backup、receipt 或日志。

Profile boundary

不在转换中管理 API Key

本轮只接入可选 profile_id；API Key、模型和环境变量由 Profile 功能独立管理。

No subprocess

转换不启动 Codex

AD 直接实现磁盘契约；用户点击 Launch 后才正常启动 Codex。

No LSP bridge

本轮不引入 sidecar

LSP-only 显示具体 unsupported；MCP bridge 需要独立供应链与安全评审。

自动安装的执行契约

Prepare/Preview 只解析和 stage；Apply 才事务写入；Launch 不安装。实现必须按以下依赖顺序产生 MutationPlan。

执行里程碑

M1

Runtime 与 conversion contract

建立 default/project home fixtures，锁定 config/plugin 零写入、共享登录、稳定 identity、launch binding 与 conversion dispositions。

验证：测试先因没有 derived installation、auth binding 与 isolated target 而失败
M2

Runtime + config + auth binding

实现 registry、base/overlay 合成、文件 auth link、Keychain-only 阻塞、path relocation、freshness 与 conflict。

验证：文件登录无需重复；Keychain-only 不假成功
M3

Directory 安全事务

稳定 tree digest、staging、APFS clonefile 可选优化、普通 copy fallback、备份、补偿与 rollback。

验证：中途失败和 target drift 均不破坏 default/project home
M4

Prepare → Preview → transactional install

临时 stage 解析/转换 package；Apply 按 auth link、marketplace、versioned cache、config 激活顺序执行，后置校验并生成 receipt。

验证：默认 store 不变；config 最后写；失败无悬空 enabled；重复 Apply unchanged
M5

Package-first conversion

完整 package 优先；legacy Skills/Commands/Hooks/MCP 进入 Project carrier fallback；partial 保留遗留项。

验证：LSP-only 不生成空 package，disabled 不计失败
M6

Scoped launch + Profile + UI

Runtime card 展示共享认证方式和可选 Profile；LaunchRecipe 注入精确 HOME/cwd/profile。

验证：Plugin 作用域不同，但用户登录态相同
M7

审查、文档与全量门禁

检查 installation confusion、write leak、path relocation、symlink escape、敏感数据排除与 rollback。

验证：Rust/前端/生产构建通过；真实 harness 只读 preview
