概念模型

从「profile 是项目状态」到「profile 是只读模板」

profile 仍然存活，但语义收窄到"初始化 / 切换时复制内容的源头"；编辑 profile 不再影响已经从它生成的项目。

┌─ ~/.ad/profiles/<id>.json (template, read-only relative to projects) │ layers: { shared, local, env } │ │ ╔═══════════════════════════════════════════╗ │ ◯───┄┄ init from template ┃ ◯──── re-apply (switch template) │ │ ╚═══════════════════════════════════════════╝ │ │ ▼ ▼ ◯ <project>/.claude/settings.json ← truth source (shared layer, git-tracked) ◯ <project>/.claude/settings.local.json ← truth source (local + env, gitignored) │ └─ edit in ProjectDetail main pane (3 tabs) — Save 即落盘，无 Apply 步骤

关键决策

设计取舍

D1

Project 真理源 = .claude/settings*.json

不再镜像到 ~/.ad/。CC 自己读这两个文件，多一份镜像必然漂移；APFS 原子写已能保证一致性。

no mirrorsingle source
D2

env → settings.local.json 顶层 env 字段

env 通常含 API key 等敏感值；settings.json 走 git，不适合存敏感值。settings.local.json 是 gitignored，正合适。

CC nativeremove export UI
D3

Save 即落盘，无 Apply 按钮

用户已确认。per-project 后没有"先暂存、再下发"的延迟写入需要。Save → write_atomic + 备份。

one-step
D4

Template 编辑入口收敛到独立位置

避免主区被 template / project 两类编辑混淆。drawer 仍然在，但只用于 template；触发器移到 ⌘K palette。

UX clarity
D5

抽 LayeredSettingsEditor 公共组件

ProfileEditor 和 ProjectConfigEditor 都需要 Monaco JSON + KV env 表 + 校验提示，分两份会立刻分叉。

DRYcontrolled
D6

HeroCard / LayerStack / ProfileCards / ApplyBar 全删

这些都是「展示 profile + 选切换」的 UI，per-project 后失去意义。Switch template 走 palette。

删旧 UI
D7

不做存量数据迁移

现有项目的 .claude/ 已经是真实状态，新模型直接读它；profiles 保持为 templates，无需改 schema。

zero-migration
D8

Profile 全局生效（legacy）保留

用户明确要求保留：activate_profile IPC、showLegacyActivation 开关、[Activate (legacy)] 按钮全部不动。给"只想全局换配置"的兜底场景。

keep legacyno IPC change

开始前需要承认的事

A1项目当前状态的真理源是 <project>/.claude/settings*.json，AD 不再额外维护"项目侧 profile"文件。
A2~/.ad/state/projects.json 的 currentProfileId 改为"最近一次从哪个 template 初始化或重置"，仅历史溯源用，不再决定 UI 状态。
A3~/.ad/profiles/<id>.json schema 不变（layers: { shared, local, env }），不做新一轮迁移。
A4CC 的 settings 支持顶层 env: { KEY: VALUE } 字段（来源：用户回答 + Claude Code 官方 env-vars 文档）。
A5Save 走原子写 + 备份（沿用 write_atomic + ~/.ad/backups/）。
A6Switch template 仍然走 apply_profile_to_project + 冲突解决，不是无声覆盖。
A7底层 read_project_settings / write_project_settings IPC 保留，新主区编辑器复用。
A8v0.1 全局激活路径（activate_profile IPC + 覆盖 ~/.claude/settings.json + legacy 开关 + Activate 按钮）整条保留，本次重构不动它的代码 / IPC / 备份行为。
验收

完成标准

AC1 — 从 template 创建项目：settings.json + settings.local.json 都被写入；env 出现在 settings.local.json 顶层 env 字段；不再出现 export 片段 UI。

AC4 — 删 ProjectSettingsSection 后 UI 不再出现"项目配置 / settings.local.json"折叠区。
AC5 — ⌘K palette 出现 "switch template" 命令；选完 → 走 merge / 冲突解决；不会无声覆盖。
AC6 — Advanced settings 开 legacy → template 编辑器（drawer）仍出现 [Activate (legacy)] → 点击后 ~/.claude/settings.json 被 profile 覆盖；当前项目的 .claude/settings*.json mtime 不变。
AC7 — pnpm typecheck / pnpm lint / cargo check / cargo clippy / cargo test 全绿。
