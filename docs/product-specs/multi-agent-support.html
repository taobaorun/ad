Product specification · multi-agent support

管理 Agent 实例，而不是复制一套 Agent UI

已批准

Claude Code 与 Codex 提供配置、Profiles、Skills、Plugins、进程探测和终端启动的用户任务级对等；Claude → Codex 转换保持源不变，目标写入统一经过预览、备份和可恢复执行。

1. 用户结果

隔离

选择一个 canonical installation 和项目后，只查看和修改该 AgentContext 的资源。profile identity 为 (agentId, profileId)。

透明

界面显示真实配置来源、scope、可用 operation 和限制；缺少等价能力时明确 degraded/unavailable。

安全

任何写操作先预览，全部目标先备份，外部修改通过 digest 检测，失败返回明确 receipt。

可扩展

未来 Agent 通过内置 adapter 和集中 UI registry 接入，不在通用 command、store、component 中散布分支。

2. 产品模型

Capability 来自可调用端口，并同时描述 scope、operations、availability 和 limitations；不能靠 enum 标签自报支持。

3. 核心流程

1
Discover
adapter 发现 candidates、计算 canonical identity；registry 只返回去重 installation。
2
Inspect
adapter 读取 allowlist resources，返回 opaque snapshot、location、format 和 digest。
3
Plan
adapter 验证 payload 并生成 backend-owned MutationPlan；UI 只收到可展示 plan view。
4
Confirm and apply
用户只确认 planId；ExecutionEngine 重新检查 digest、完成全部备份后逐文件原子写。
5
Receipt and rollback
返回 complete/compensated/partial failure；rollback 不覆盖 apply 后用户新修改。

5. 数据安全

Managed allowlist

settings、instructions、skills、plugins、hooks、MCP、agents、rules 可由 adapter 显式列入。

Permanent exclusion

auth、token、session、history、logs、cache、SQLite 永不进入 snapshot、diff、backup 或日志。

Single writer

adapter 只 inspect/plan；ExecutionEngine 是唯一写入入口。

Honest failure

多文件更新不宣称整体原子；补偿结果必须区分 complete、compensated 和 partial failure。

6. 验收标准

  • Claude/Codex 五类 P0 能力通过共享 operation-level contract suite。
  • 相同 config home 多来源只返回一个 canonical installation；不同 home 不被合并。
  • profile、project state、history、backup 和 receipt 不跨 AgentContext 串写。
  • Claude → Codex source 字节不变；已有 target 在确认前不写入。
  • backup、digest conflict、compensation、partial receipt 和 rollback 有故障注入测试。
  • 新 built-in adapter 不修改通用业务路径。
  • typecheck、lint、frontend tests、Rust tests 和 build 全部通过。

7. 边界

Always
  • adapter 解析 Agent 路径和格式
  • ExecutionEngine 统一写盘
  • 结构化错误 + schema-validated IPC
  • 旧 Claude 行为兼容到迁移完成
Ask first
  • 新增依赖或 Tauri 权限
  • 改变 Claude 文件语义
  • 删除用户文件或迁移数据位置
  • 扩大 allowlist 到认证/运行时状态
Never
  • 动态或用户配置 adapter
  • 未备份覆盖目标
  • conversion 修改 source
  • 前端提交目标路径或 mutation content
  • partial failure 当成成功
