Project Agent Workspace

把本地 Agent 配置重新交还给项目。

AD 以项目为中心统一呈现 Claude Code 与 Codex 的 Settings、Skills、Plugins、来源、覆盖关系、操作记录与转换结果。每次写入都先被证明，再被确认，最后留下可恢复的证据。

完成不是“按钮存在” Project A 不影响 Project B；unknown 不伪装成 complete；每个 Apply 都有 plan、receipt 和受保护 rollback。
01 · Product promise

四个必须完成的用户任务

01

理解最终配置

按 user、project shared、project local/runtime 解释 effective winner、来源与只读边界。

02

管理全部 Skill

source 进入受限 staging，再发布不可变 artifact；项目独立 pin，external 保持只读。

03

管理全部 Plugin

Claude 使用项目 override；Codex Plugin 落入隔离的 Project Runtime，不污染默认 Home。

04

安全转化配置

Settings、Skills、Plugins 分载体转换；unresolved 阻止完整 Apply，safe subset 由用户明确选择。

06 · Boundaries

管理能力对等，不等于自动化入口对等

AD 现在保证

  • 第一方 UI 内的项目配置管理与安全确认。
  • 真实 capability、coverage、ownership 与 residual。
  • 按项目隔离的 plan、receipt、history 和 rollback。

AD 现在不宣称

  • 公共 CLI、MCP、deep-link 或远程 approval API。
  • 第三方 Skill、Plugin、hook、MCP 的执行沙箱。
  • Keychain-only custom Home、connector 授权或 User Plugin acquisition。
