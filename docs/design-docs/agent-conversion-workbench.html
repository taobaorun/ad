Agent 配置转换工作台

转换不再等于“生成一份很短的 config.toml”。新模型先完整盘点 Claude 配置，再把每项路由到 Codex 的真实载体；无法迁移可以明确失败，危险权限不能静默放行。

已确认 · 2026-07-16

四条反馈，一个根因

当前界面把配置实例、本次资源、转换决策和应用确认混在一起，导致“看得到状态，但无法完成任务”。

路径表意

Project 仍显示用户目录

~/.claude 与 ~/.codex 是 installation home，不是本次 Project 资源。单实例时隐藏，多实例时放进高级区。

覆盖率

config.toml 只有少数字段

Settings、Skills、Plugins 使用不同载体。问题不是文件短，而是其他项目没有明确目标、动作和结果。

安全

危险权限没有真正确认

红色提示不等于确认。现有通用 confirmed: true 无法绑定具体风险，必须由后端 plan 声明和校验。

Artifact → Carrier 路由

通用层只管理 inventory、状态、风险和执行安全；每个内置 adapter/route 决定真实载体与可转换语义。

source 永远只读可安全写入的 target carrier需要后续设置，不报告假成功

危险权限：提示不等于确认

独立二次确认

允许 Codex 无审批、无沙箱运行？

此变更会扩大项目中的命令执行权限。Claude Code 配置不会被修改，但 Codex 可在本机拥有完全访问。

approval_policy = "never"
sandbox_mode = "danger-full-access"
取消确认危险变更并应用
后端硬门禁

Plan-bound acknowledgement

风险来自 backend-owned mutation plan。PlanStore 保存 dangerous_permission_expansion requirement；Apply 必须提交精确 acknowledgement。空值、未知 code、旧 plan、通用 boolean 都拒绝且不消费计划。

不可绕过的不变量只有当前 plan 的所有 required acknowledgements 满足后，才进入 digest 复查、备份和写入。

sofampy 验收基准

真实项目只做 preview；Apply/rollback 使用同形临时 fixture。合法结果可以是“不支持”，但每类来源必须可见。

设计验收

完整性

每个源 artifact 恰好一次

自动、待决策、unsupported、conflict、unchanged 五类都可追踪；没有 resolver 的项目不能标 requires_input。

数据安全

源不变，目标可恢复

source 只进入 read-set；target 全量写前备份；文件和 symlink 均有 receipt 与 digest-protected rollback。

可理解

真实载体优先

Project path 和实际 resource locations 在主区；installation home 仅在高级选择中出现。

强制确认

危险风险绑定计划

普通 Apply 不能带过危险权限；前后端测试共同证明确认路径存在且不可由 generic boolean 绕过。
