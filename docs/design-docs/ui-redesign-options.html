UI 重设计：三个方向并排

当前 AD 的三栏布局（Profiles | Editor | Projects）在分层 profile 模型下信息架构错位 —— 左栏的 profile 列表跟主路径（per-project apply）脱节，三个加项目入口并列， profile 三 tab 等权重塞 monaco + 表单，ApplyDialog 把流程全挤进一个模态框。 本文档给三个完全不同的重设计方向，每个都能解决主要痛点但侧重不同。 请挑一个（也可以指出要合并的部分），我再基于它创建 ExecPlan。

九个痛点

  1. P1信息架构错位 · profile 列表和 project 列表并列，但实际关系是"profile 应用到 project"，UI 上看不出来
  2. P2左栏 profile 跟主路径脱节 · 选中左栏的 profile 不会影响 ApplyDialog 里的默认 profile
  3. P3三 tab 同权重 · Local（日常）、Shared（团队稀有）、Env（手贴）认知频率差几十倍，但 UI 等大
  4. P4ApplyDialog 拥挤 · profile select + 3 layer checkbox + dirty 警告 + status 信息 + outcome 全塞一个 modal，outcome 还压在按钮上面
  5. P5三个加项目入口并列 · type path / drop zone / detected banner，挤一块右栏顶
  6. P6没有 active project 概念 · 项目平铺，但你日常只在 1-2 个项目工作，没有 pinned / recent
  7. P7History 埋在左栏底 · 跟 profile 列表关系不强，但占了主导航位置
  8. P8冲突 UI 只读 · ApplyDialog 出冲突只能看，不能选 keep/use/custom（TD-005）
  9. P9Titlebar 显示 legacy active · "active: work" 是 v0.1 全局激活概念，新模型下基本没意义

三个重设计方向

差异故意拉大 —— 信息架构、主路径、视觉中心都不同。挑一个或要求合并。

方向 A · PROJECT-CENTRIC
项目即工作台
项目卡片 grid 占主视图，profile 是工具栏里的可选项。 像 macOS Launchpad —— 你工作的对象是项目，profile 只在 apply 时出现。

主路径

  1. 顶 ⌘K 搜索或粘路径 → 项目卡片立刻 pin
  2. 卡片右下角的 chip work · L+E 点开 → inline 切换 profile / layer
  3. "应用"是卡片本身的 mode —— 卡片 hover 出 [Re-apply] / [Diff] / [Open]

解决了

P1 P5 P6 P7 P9 P2 P4
Tradeoff：profile 编辑下沉到二级页面（顶 toolbar 的 Profiles 按钮 → 打开抽屉）。 单纯调 profile 不应用的场景需要多点一次。
方向 B · RECIPE & WORKSPACE
配方 + 工作台
像 Postman / Insomnia：左栏 collection（profile 即 recipe）， 主区是当前 workspace（一个项目）—— inline 出 diff / apply / conflict resolver，不再用 modal。

主路径

  1. 顶 workspace switcher 切到目标项目（最近的固定置顶）
  2. 左栏挑 profile → 主区域 inline 出 diff + 冲突 resolver（不再 modal）
  3. 勾 layer chip → 底部 [Apply L/Shared/Env] 是个分段按钮
  4. profile 编辑 = 在左栏点 profile name → 切换到 Edit 子页（同主区域）

解决了

P1 P2 P3 P4 P5 P8 P9 P6 P7
Tradeoff：workspace 一次只看一个项目，对比/批量 apply 多个项目要切。 切 workspace 的开销靠"最近项目固定置顶 + 快捷键"补，但本质是单焦点视图。
方向 C · CONNECTION GRAPH
配对视图 + 关系可视化
左 profile · 中 关系 canvas · 右 project —— 点 profile 高亮所有用它的 project，点 project 高亮当前 profile。 应用 = 在两边各选一个 + 看 canvas 中间的 diff。

主路径

  1. 左 profile · 右 project 各点一个 → 中间 canvas 自动出 diff + layer chips
  2. 点 profile 高亮右栏所有使用它的 project（暗化其他）
  3. 底部一条横向 Apply A → B 主按钮，没有 modal
  4. profile 编辑 = 右键 / cmd-click profile → drawer 弹出三 tab

解决了

P1 P2 P4 P6 P8 P9 P3 P5 P7
Tradeoff：视觉密度最高、最炫，但学习曲线最陡。 profile 编辑下沉到 drawer 后，正在编辑时跟主视图脱节，需要靠 inline preview 缓解。 不熟 AD 的人看到三栏 + canvas 可能反而懵。
方向 A′ · CMUX-INSPIRED
⌘K + 富 sidebar（A 的升级版）
借鉴 cmux 的 vertical-tab sidebar + command palette 思路： 紧凑 project 列表 + 富 metadata row + 状态色环 + ⌘K 触发所有动作 + 键盘快捷键全覆盖。 A 是大卡片浏览风格，A′ 是 power-user 风格。

主路径

  1. ⌘K 是入口：所有动作都从这里触发（add project / apply / switch / edit / open）
  2. 左 sidebar 紧凑 row，色环表达状态（🟢 synced / 🟠 dirty / ⚪ idle）+ ⌘1-8 直接跳
  3. 主区域显示当前 project 的状态卡 + "Apply different profile" 区（chips + layer toggles + ⌘↵ apply）
  4. profile 编辑也走 ⌘K: "Edit profile work" → 滑出抽屉

跟原 A 的区别

原 A 是大卡片 grid（适合浏览），A′ 是紧凑 sidebar + 详情主区（适合 power user）。 sidebar 一眼看完所有 project 状态，主区聚焦当前操作；快捷键覆盖所有路径，鼠标可选。 借鉴 cmux 的 sidebar row 富 metadata（git branch、PR、layers、last apply、ring 状态）。

解决了

P1 P2 P4 P5 P6 P7 P9 P3 P8
Tradeoff：对键盘党最爽，但新手第一眼看到全是缩写和快捷键标号会懵； 需要 onboarding 提示。富 sidebar row 信息密度高、字小，对宽屏友好对窄屏一般。
