1. 三层身份，而不是一个 AgentId

canonical identity 由 adapter 按“有效配置 home”计算。同一二进制使用两个 CODEX_HOME 是两个 installation；多个 launcher 共享一个 home 时只保留一个 canonical installation。discovery evidence 可以诊断，但不作为 aliases 持久化。

2. 能力来自端口，不来自自报的 enum

当前 v0目标 v1为什么
Set<Capability>settings() -> Option<&dyn SettingsPort> 等端口不存在就不能宣称支持
只区分 settings / skills / plugins同时声明 scope、operations、availability、limitations能验证用户任务级对等
enum set 相等即 paritycontract tests 验证 read/edit/preview/apply/rollback防止“假支持”
trait AgentAdapter {
  fn definition(&self) -> &AgentDefinition;
  fn discover(&self, ctx: &DiscoveryContext) -> Result<Vec<Candidate>>;
  fn settings(&self)  -> Option<&dyn SettingsPort> { None }
  fn skills(&self)    -> Option<&dyn SkillsPort> { None }
  fn plugins(&self)   -> Option<&dyn PluginsPort> { None }
  fn processes(&self) -> Option<&dyn ProcessPort> { None }
  fn launcher(&self)  -> Option<&dyn LaunchPort> { None }
}

3. 通用层只认识 Resource 和 Snapshot

ResourceRef

installation、可选项目、kind、scope、logical id。路径由 adapter 解析，前端不能提交任意绝对路径。

ResourceSnapshot

location、media type、opaque content、digest、observed time。common layer 不解释 JSON/TOML 字段。

AgentProfile

稳定 envelope + (agentId, profileId) + payloadSchema + adapter-owned payload。

Allowlist

auth、tokens、sessions、history、logs、cache、SQLite 永不进入 snapshot、diff、backup 或日志。

Codex 的 settings、AGENTS、skills、plugins、hooks、MCP 和 rules 是不同 artifact，不再被压扁成一个 config.toml 字符串。

4. adapter 规划，ExecutionEngine 唯一写盘

UI 提交 backend-owned planId；转换计划还必须提交 plan view 声明的 typed acknowledgements。PlanStore 精确匹配 acknowledgement 集合，危险权限不能由通用 boolean 绕过。执行前重新验证 read/write digests，先完成全部备份，再逐文件原子写。

5. 转换是多载体 artifact route

1
锁定单一 scope
无 projectPath 只处理 User；有 projectPath 只处理该 canonical Project。
2
盘点并展示真实路径
每项携带 source/target location、disposition、resolution、risk。
3
按 carrier 路由
Settings → .codex/config.toml；Skills → .agents/skills；Plugins → marketplace 后续设置。
4
组合 target ports
Settings 与已确认本地 Skill 组成一个 digest-bound、可回滚计划。
5
分离规则与风险
细粒度 permission rules 单列 unsupported；危险预设要求独立确认。
6
确认、执行、回执
source 只读；目标备份后写入；receipt 支持 rollback。
Workbench 单 installation 隐藏配置实例；多实例收进高级区。主区只展示 adapter 解析出的实际 resource location。Project-only Plugin 与 marketplace 逐项可见，没有安全安装 API 时不伪造成功。
