2. 身份与能力

Identity

Definition → Installation → Context

adapter 按有效 config home 计算 canonical installation。多个发现来源只保留去重结果；每次操作由 installation 与可选 project 组成隔离上下文。

Capability

能力来自真实端口

Settings、Skills、Plugins、Process、Launch 端口推导 scope、operations、availability 和 limitations。没有端口就不能自报支持。

Profile

复合身份与自有 payload

(agentId, profileId) 允许同名 Profile 隔离共存；Claude JSON 与 Codex TOML 分别由对应 adapter 验证和转换。

Boundary

只支持内置 adapter

用户可以选择 installation，但不能通过 manifest、脚本或配置定义新的 Agent adapter。

3. 安全执行路径

1
Inspect — adapter 读取 allowlist resource，返回内容、位置和 digest。
2
Plan — adapter 校验编辑或 Profile payload；后端保存完整 MutationPlan，UI 只看 view。
3
Confirm — apply 只提交 planId；conversion 使用后端强制的专用确认路径。
4
Execute — 重验 digest，先备份所有目标，再以 APFS rename 逐文件原子写。
5
Recover — receipt 记录 complete / compensated / partial_failure；rollback 拒绝覆盖 apply 后的新修改。

5. 数据位置

Profiles

~/.ad/profiles/<agentId>/<profileId>.json

Backups

~/.ad/backups/operations/<receiptId>/

History

~/.ad/history/operations/<receiptId>.json

Agent homes

~/.claude、~/.codex / CODEX_HOME 与项目目录，由 adapter 解析。

永久排除：auth、token、credentials、session、prompt/chat history、logs、telemetry、cache、SQLite 和索引不会进入 snapshot、diff、backup 或日志。
